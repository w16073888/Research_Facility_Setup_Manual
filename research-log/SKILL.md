# 研究日志

给这个 Obsidian 库（`D:\大学编程学习\obsidian`）写研究日志。、。

日志的价值不仅在"我今天干了啥"，也在为什么这么干，但最重要的是**简洁**。

## 一、动笔前先做四件事

1. **拿今天的日期**：`date +%F`。
2. **查今天是否已经记过**：`ls 日志/$(date +%F)-*.md`。
   ⚠️ **有 → 这是「扩写」，不是「新建」**，按 §二「同一天只留一篇」办。
   **一条命令就能避免同一天开出第二篇**，务必先跑。
3. **读上一篇**：`ls -t 日志/*.md | head -1`，读它的结论和它留下的 `## 待完成`。
   （若第 2 步查出今天已经有日志，那"上一篇"就是**今天这一篇**——直接读它、接着往下写。）
   - 上一篇的待办这次做完了 → 在正文里交代结果；没做 → 原样带进新日志的待完成。

## 二、存放与命名

- 目录：`日志/`，**平铺，不建子目录**
- 文件名：`YYYY-MM-DD-标题.md`
- 标题用 `·` 或 `与` 连接两个概念，**文件名内不加空格**
- 参照已有文件：`2026-09-20-大创骨架第一步·只读网关与窄接口.md`

### 同一天只留一篇

**一天一篇，不是一件事一篇。** 同一天里又干出新的东西、又冒出新的坑，**要落进已经存在的那一篇**。

动手前必跑：`ls 日志/$(date +%F)-*.md`

**已经有一篇 → 扩写它**，具体怎么做：

| 动作 | 要求 |
|---|---|
| 新内容往哪放 | **按主题并入对应章节**。能并进去就并，**不要在文末堆一段「补充」**|
| 章节编号 | 并入后**重排 `## 1.` … `## N.`**，不要出现两个 `## 3.` |
| `## 待完成` | 原来那条这次做掉了 → **勾掉 `[x]` 或改写**。别让同一件事既在"待完成"里躺着、正文里又说已完成|
| `## 发现的问题` | 新坑**按严重程度插进去**，不是追加到末尾 |
| `tags` | 新内容确实引入了新主题就补，但**别堆** |
| 顶部 `> 承接` | **不动**——它承接的是"那一天"，不是"那一段" |

**没有 → 才新建**，按上面的命名规则。

### ⚠️ 扩写时不要改文件名

标题覆盖的是**那一天的整条线**，所以名字一旦定下就**别再动**。

- 新内容超出旧标题的覆盖范围了？**接受它**——一天之内的事本来就是一根线上长出来的。
- **真要改名，必须是用户明确要求**。 
  **用户没提就不改**，改了会打断所有指向它的 `[[双链]]`。

> **例外（要问，不要自己决定）**：同一天里确实是**两条不相干的线**
> 但**默认是合成一篇**，分不分**先问用户**。


## 三、正文

从 `templates/日报.md` 起手。章节顺序：

| 段落 | 内容 | 必要性 |
|---|---|---|
| `**环境**` 表 | 库路径 / 工具版本 / 模型 / 数据规模 | 涉及具体环境时必写 |
| `## 1.` … `## N.` | 按主题分的正文，**不是按时间流水账** | 必写 |
| `## 发现的问题` | 见第五节 | 有问题就写，没问题可省 |
| `## 待完成` | `- [ ]` 复选框 | 必写 |
| `## 相关` | `[[双链]]` | 必写 |

## 四、写「发现的问题」的规矩

这是整篇日志最值钱的部分。铁律：

1. **按严重程度排，最严重的标 `【最严重】`**。
2. **三段式**：现象 → 根因 → 证据。证据要贴**原始输出**（报错原文、命令、SQL、日志行），不要只给转述。
3. **凡有数字，必是实测的**`166 MB`、`96%` —— 这种具体度是这些日志的底子。**不确定的数字不要写，标 `<!-- 待确认 -->`**。


补充手段：
- `> ⚠️` 用于会咬人的坑；`> 注：` 用于易误读的细节
- 结论有反直觉之处时，加 **"关键认知 / 结论"** 一句话点破

## 五、语言风格

- 最重要的是**简洁**！
- 中文正文，代码/路径/命令/报错原文保持原样
- **表格优先**：并列的项 >3 个就上表格，不要写成逗号长句
- 章节标题是**结论**不是**动作**
- 允许并鼓励用粗体标出关键判断
- 长度不设上限，但**不要为了长而灌水**；一句话能说完就别写三段

## 六、禁止

- **不要编造**任何数字、路径、命令输出、报错原文。对话里没有的就不写，或标 `<!-- 待确认 -->`
- **不要写成"我做了 A，然后做了 B"的流水账** —— 按主题重组
- **不要把对话原文贴进来** —— 是提炼，不是转录
- 不要建子目录、不要改已有日志的文件名

## 七、写完之后

1. **回写库根 `README.md` §2**（**硬要求，先做这一步再报告**）——
   **新建**一篇：§2 加一行 `| [[日志/YYYY-MM-DD-标题]] | 讲什么 |`；
   **扩写**今天已有的那篇：改 §2 那一行的「讲什么」。
   两种都要顺带把根 §1 里 `日志/` 那一行的「最后更新」改成今天。
   > ⚠️ **`日志/` 没有自己的 README——根 README §2 是它唯一的索引。**不回写，新会话从根 README 出发就找不到这篇日志，整棵索引树的承诺就断了。规则见 `folder-readme` skill §四「向上传播」。
2. 告诉用户：文件落在哪、标题是什么，**并说清这次是「新建」还是「扩写了今天已有的那一篇」**——
   扩写的话，报出**新增/改动了哪几节**（用户要能一眼看出旧内容有没有被动过）
3. 附一句本次对话里**还没解决**的事（如果 `## 待完成` 里写了，提醒他那就是下次的起点）
4. 如果这篇和更早的日志构成一条线，提示他可以补一条 `[[双链]]` 过去
