# 研究日志与规划（research-log）

给根目录的两个**规划文件目录**写内容，二者分工：

| 目录 | 记什么 | 节奏 |
|---|---|---|
| `日志/` | **流水账**：每天干了什么的细节——从哪搞到什么文件、踩了什么坑、实测数字、动作结果 | 一天一篇，平铺不建子目录 |
| `规划/` | **长期参考**：需要反复查阅的 md——方案、导师建议、方向决策、评估结论、迁移备忘 | 按主题一篇，长期积累 |

> 判断准则：**"三个月后还需要回头看吗？"** 要 → 规划；只是当天经过 → 日志。

**动笔前先做四件事**（日志与规划都要）：
1. **拿今天的日期**（`YYYY-MM-DD`，例如 `2026-10-14`）。
2. **日志**：查 `日志/` 里今天是否已有 `YYYY-MM-DD-*.md`。⚠️ **有 → 是「扩写」，不是「新建」**（见下）。
3. **规划**：查 `规划/` 里是否已有**对应主题**的 `.md`。⚠️ **有 → 并入那篇**，不新开同名文件。
4. **读上一篇**（日志）：`日志/` 里按文件名倒数第一/二篇，读它的结论和 `## 待完成`。上一待办做完了 → 正文交代结果；没做 → 原样带进新的待完成。

---

## 一、`日志/` —— 流水账

### 存放与命名

- 目录：`日志/`，**平铺、不建子目录**；文件名 `YYYY-MM-DD-标题.md`。
- 标题用 `·` / `与` 连接两个概念，文件名内**不加空格**。

### 同一天只留一篇

**一天一篇，不是一件事一篇。** 同一天又干出新东西、又冒出新坑 → 落进**已存在的那一篇**。动手前必查 `日志/YYYY-MM-DD-*.md`。

**已经有一篇 → 扩写它**：按主题并入对应章节（不堆「补充」）、重排 `## 1.`…`## N.`、待完成勾掉/带入、新坑按严重程度插入、顶部 `> 承接` 不动。

**没有 → 才新建**。

### ⚠️ 扩写时不要改文件名

标题覆盖那一天的整条线，名字定下后**除非用户明确要求**否则**别再动**（会打断指向它的双链棒）。

---

## 二、`规划/` —— 长期参考

### 存放与命名

- 目录：`规划/`，**按主题一篇，长期积累**。文件名 = **主题名**（不按天），如 `linux迁移评估.md`、`方向决策-本地LLM·微信·Jev.md`。
- 同一个主题已有文件 → **并入**，不新开。
- 新开规划文件时，顶部一行说明"何时记录 + 是长期参考"。

### 什么样的内容进规划

- 导师 / 外部**建议**及其**评估结论**（谁建议、契合度、改动量、怎么落地、归谁）
- **方向决策**与选型对比
- **迁移备忘**、长期有效的坑、方案级结论
- 需要新会话反复查阅的 md

### 日志 vs 规划的回写

- **日志**：新建/扩写 → 回写根 README `日志/` 节。
- **规划**：新建/扩写 → 回写根 README `规划/` 节。
- 两者都**先回写根 README 再报告**（`日志/`、`规划/` 若没有自己的 README，根是它们唯一的索引——不回写，新会话找不到。规则见 `folder-readme` skill §三）。

## 三、正文

日志从 `templates/日报.md` 起手；规划文件参照日报模板**去掉**「待完成」/「承接」等流水字段。日志章节顺序：

| 段落 | 内容 | 必要性 |
|---|---|---|
| `**环境**` 表 | 库/项目路径、工具版本、模型、数据规模 | 涉及具体环境时必写 |
| `## 1.` … `## N.` | 按主题分，**不是按时间流水账** | 必写 |
| `## 发现的问题` | 见 §四 | 有问题就写 |
| `## 待完成` | `- [ ]` 复选框 | 必写 |
| `## 相关` | 关联文件 / `[[双链]]` / **指向 `规划/` 详版** | 必写 |

> 流水账翻译：正文记**动作与结果**（从哪里下载、字节数、踩了什么坑、实测数字、改了什么文件）；**决策与评估**留在 `规划/`，日志里一行指针 + 流水即可。

## 四、写「发现的问题」的规矩

这是流水账里最值钱的部分。铁律：

1. **按严重程度排，最严重的标 `【最严重】`**。
2. **三段式**：现象 → 根因 → 证据。证据贴**原始输出**（报错原文、命令、SQL、日志行），不转述。
3. **凡有数字必是实测的**（`166 MB`、`96%`）。不确定的数不写，标 `<!-- 待确认 -->`。

补充手段：
- `> ⚠️` 用于会咬人的坑；`> 注：` 用于易误读的细节
- 结论有反直觉之处时，加 **"关键认知 / 结论"** 一句话点破

## 五、语言风格

- 最重要的是**简洁**！
- 中文正文，代码/路径/命令/报错原文保持原样
- **表格优先**：并列项 >3 个上表格
- 章节标题是**结论**不是**动作**
- 不设长度上限，但**不灌水**

## 六、禁止

- **不要编造**任何数字、路径、命令输出、报错原文
- **不要写成"做了 A 然后做 B"的流水账**——按主题重组
- **不要把对话原文贴进来**——是提炼
- 日志：不建子目录、不改已有日志文件名
- **不要把该进 `规划/` 的长期内容**只留在日志里

## 七、写完之后

1. **回写根 `README.md`**（**硬要求，先做再报告**）——`日志/` 节加/改**一行**；`规划/` 节加/改**一行**。
   ⚠️ `日志/` 与 `规划/` **若没有自己的 README，根 README 是它们唯一的索引**。不回写，新会话找不到。规则见 `folder-readme` skill §三。
2. 告诉用户：落在哪、标题是什么，并说清是「新建」还是「扩写/并入了已有的那篇」。
3. 附一句本次对话里**还没解决**的事（`## 待完成` 里的就是下次起点）。
4. 若与更早内容构成线，提示可补双链。
